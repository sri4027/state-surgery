## 1. The one-sentence claim

> A recurrent model with **frozen weights** can acquire an unseen colour rule purely by updating a
> **fixed-size state** as it reads demonstrations — and that state is the **sole carrier** of the rule:
> transplant it and the rule transplants with it, erase it and the rule is gone.

The claim is falsifiable and the artifact is built to falsify it. Press **Forget** and the rule
disappears. Press **Move A's state into B** and the model applies A's rule to B's input. If the state
were not the carrier, neither would happen.

## 2. Audience, prerequisites, learning objectives

**Audience.** Anyone comfortable with "a neural network has weights". Acts 1–3 need no ML background;
the BDH module assumes familiarity with attention.

**Prerequisites.** None for the interaction. For the BDH module: what attention and a KV cache are.

After using it, a learner can:
1. State where a demonstration-acquired rule is stored, and give the evidence.
2. Distinguish **test-time training** from **test-time adaptation** and say which BDH-CQ does.
3. Explain why "the weights changed" and "nothing was learned" are *both* wrong.
4. Predict what happens when the state is erased, swapped, or randomised — before clicking.
5. Explain why a model can fail on a held-out case for reasons of **demonstration coverage**
   rather than reasoning capacity.
6. Say what BDH's evolving ruleset σ is, and how BDH-CQ's Eqs. (1)–(4) map onto it.

## 5. The model

298,720 parameters. A 128x128 = 16,384-entry fixed-size state. 6x6 grids, 10 colours.

* **Writer** `U_θ`: each demonstration cell -> ReLU-lowrank block -> sparse positive key and a value ->
  `S = Σ_t k_t ⊗ v_t`. This is the additive special case **named in BDH-CQ Eq. (1)**.
* **Reasoner** `F_θ`: `H_{r+1} = F(H_r, S, Q)`, R steps, decode at the end. BDH-CQ Eqs. (2)–(4).
* Weights are frozen at inference. SHA-256 of the parameter buffer is identical before and after
  ingesting demonstrations; `||Δθ|| = 0` exactly (`E8` in `results.json`).

### Three engineering findings worth reporting

1. **Additive embeddings make the mechanism impossible.** Summing colour and position embeddings makes
   `key(colour,pos)` inseparable from positional noise of equal magnitude, so no colour-specific key can
   form and the normalised read degenerates to the mean of all values. Accuracy pinned at the
   background-only baseline. Factored coordinate blocks fixed it outright: 0% -> 100% strict grid.
2. **This is BDH's own problem.** BDH Sec. 6.1 discusses state capacity versus *distinction* capacity.
   We hit it empirically at 10^5 parameters.
3. **We isolated it correctly.** A stripped-down keyed associative memory reached 100% strict grid
   immediately, proving the mechanism was sound and the plumbing was not.

## 6. Results

All figures from `web/results.json`, held-out tasks, evaluation seed 20260908.
Strict grid = all 36 cells correct.

**Demonstrations are necessary**

| demos | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| strict grid | 0.0% | 84.8% | 98.8% | 99.6% |

**What the state has to be** — correct 98.8% · zeroed 0.0% ·
another task's 0.0% · random scale-matched 0.0%

**Transplant (the central test), 256 held-out pairs, matched palettes, 0 rule collisions**

| condition | scored against | strict grid |
|---|---|---|
| B's own state | rule B | 100.0% |
| A's state on B's query | rule B | 0.0% |
| A's state on B's query | **rule A applied to B** | **100.0%** |

The second number is the point. The model is not confused and not producing noise; it applies A's rule
exactly and confidently to B's input. A *predictably wrong* answer produced by moving one named
variable is stronger evidence than a correct one.

**Coverage cliff — query byte-identical across conditions**

| | cells whose colour was shown | cells whose colour was NOT shown | strict grid |
|---|---|---|---|
| short (3 demos) | 100.0% | **0.0%** | 2.3% |
| + 1 supporting demo | 100.0% | **99.4%** | 98.8% |

0.0% is *below* the 11.1% of guessing. The model is not
guessing; it is confidently applying a binding that does not exist. This is the miniature of BDH-CQ
Table 3, where matched support took depth-5 nesting from 19/24 to 24/24.

**Binding capacity** — strict grid stays at or above 97.4% for 2 through 9
simultaneous bindings, extrapolating past the 3–6 seen in training. BDH-CQ reports the same shape
(24/24 at every level from 2 to 8 bindings).

**Within-task consistency** — pair 99.9% vs strict-task 99.6%,
a gap of 0.26 points. BDH-CQ reports an 18.5-point gap on ConceptARC. Our toy applies its
rule consistently; the full system does not yet.


**Reading the rule out of the state.** One forward pass on a probe grid containing every colour once;
whatever the model emits at colour *c*'s cell is what the state says *c* maps to. This is the model's
own read-and-decode path, not a surrogate.

| demonstrations | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| colours demonstrated | 9.6% | 91.8% | 99.2% | **99.7%** |
| colours never shown | 8.5% | 0.0% | 0.0% | **0.0%** |

Chance is 11.1%. With zero demonstrations the whole readout sits at 9.2% — the state
says nothing because there is nothing in it. This method is the recurrent-state analogue of the
extract-and-patch protocol Hendel et al. (2023) apply to Transformer hidden states.

**Interference — the cost of a fixed-size carrier.** Because the write is additive, K tasks can be
superposed into one state, `S = S₁ + … + S_K`. A growing KV cache would simply store more; a fixed-size
state has to share.

| rules superposed | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| strict grid | 99.5% | 35.9% | 19.3% | 9.9% | 7.3% | 3.1% |

The decoded rule degrades gradually rather than vanishing, which is what interference in an associative
memory looks like. This is the cost the PS's own example claim points at: a fixed-shape state handles
unbounded input but can still forget through interference.

**Latent reasoning steps — an honest negative result.** Strict grid is flat at
99.5% for R = 1 through 8. Our task needs one associative lookup, so extra latent
steps have no work to do. We report this rather than hiding it, and it is why we did not build the
central claim on inference-time compute.

## 7. Leakage and shortcut audit

* **Fresh permutation per task.** 9! = 362,880 permutations, drawn at generation time. The specific rule
  was almost certainly never trained on, so success cannot be retrieval of a memorised task family.
  This is the design constraint the whole project is built around, and it is BDH-CQ's own
  contextual-binding probe (§6.3).
* **Query-only shortcut** ruled out: another task's state on this query scores
  0.0% strict grid.
* **State-magnitude shortcut** ruled out: a random scale-matched state scores 0.0%.
* **Demonstration order**: our additive write is *exactly* permutation-invariant, so order cannot be a
  cue. BDH-CQ's memory is order-dependent. This is a documented difference between the systems,
  not a result about BDH-CQ.
* **Parameter identity**: SHA-256 before == after, `||Δθ|| = 0`.

## 9. Known limitations

0. **The rule readout is a decode, not a probe of internal structure.** It tells you what the state
   *causes the model to output*, which is exactly the claim being made. It does not tell you how the
   binding is represented inside the 16,384 numbers, and we make no claim about that.
1. **Colour binding only.** Structural operations (mirror, rotate, transpose) are **not** learned.
   We attempted the joint family, could not train it at this scale, and scoped down rather than
   overclaim. Reported as a limitation, not omitted.
2. **Cell-aligned demonstration tokens.** Input and output colour of the same cell share one token.
   This is what restricts the family in (1). Disclosed in the artifact.
3. **R has no effect.** No latent-compute scaling is reproduced or claimed.
4. **Our state is ~5% of parameter count**, whereas BDH targets parameter-scale state (`n ≪ m ≪ n²`),
   and it is a dense matrix rather than a sparse synapse graph.
5. **6x6 grids, 10 colours, 1–4 demonstrations, palettes of 3–6 in training.** Anything else is
   extrapolation and labelled as such in the artifact.
6. **This is not BDH-CQ.** No shared weights or code. No BDH-CQ checkpoint is public and its
   dimensions and update rules are proprietary, so no faithful reimplementation exists — ours included.
