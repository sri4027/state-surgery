Where does a learned rule actually live?

A recurrent model with frozen weights can acquire an unseen colour rule purely by updating a fixed-size state as it reads demonstrations — and that state is the sole carrier of the rule: transplant it and the rule transplants with it, erase it and the rule is gone.

Everything on this page marked live is computed in your browser by a hand-written forward pass over a 298,720-parameter model trained for this artifact. Audience: anyone comfortable with "a neural network has weights". No ML background needed for Acts 1–3. 15 seconds: press Forget.

Why build a model this way? BDH and BDH-CQ published

You have just watched a fixed-size state carry a rule. That is the design premise of Pathway's Dragon Hatchling (BDH) family. In an ordinary Transformer, in-context learning is carried by a key–value cache that grows with every token. In BDH the carrier is a recurrent associative state whose size does not depend on context length.

BDH: adaptation has somewhere to live

BDH splits the model into a fixed ruleset (the trained weights) and an evolving ruleset σ — a synaptic state updated by a Hebbian rule as the model reads. The design point is capacity: a classical RNN carries O(n) state, a fast-weight system O(n²), and BDH deliberately sits between them on a sparse graph of m synapses, n ≪ m ≪ n². Because the state is parameter-scale, a task rule can be held in it. BDH-GPU realises this as linear attention in a high neuron dimension with ReLU-lowrank blocks and sparse positive activations (~5% of neurons active). Note: BDH is not an SSM in the Mamba sense — BDH-GPU is a separate formulation.

BDH-CQ: the published interface

BDH-CQ adds an interface for learning visual transformations from demonstrations. Given demonstrations D={(x_t,y_t)} and query x*:

S_t = U_θ(S_{t-1}, D_t) (1) θ stays fixed additive special case named in the paper: S_t = S_{t-1} + U_θ(D_t)
H_0 = E_θ(x*, S_K) (2) H_{r+1} = F_θ(H_r, S_K), r = 0 … R−1 (3) ŷ = G_θ(H_R) (4)

The two states have different jobs. S changes as evidence arrives and is what in-context learning writes into. H carries the computation for the current query and is never decoded into language. Conflating them is the most common misreading. Note that S_K conditions the encoder and every reasoning step.

Where our toy sits

Published BDH-CQ results published

Evidence labelling. The 29.5% figure is a system result, not an architecture result: the evaluated system includes input transformations, candidate construction and ranking. The paper reports an independent black-box audit that reproduced it — conducted by co-authors from Bielik AI and NYU, without weights access, under a documented protocol. That is stronger than a bare developer claim and weaker than a fully external replication, and it should be called what it is. No BDH-CQ checkpoint is public and its dimensions and update rules are proprietary, so nobody can faithfully reimplement it, us included.

The misconception this artifact exists to kill

✗ "The weights changed."
They did not. The SHA-256 of the parameter buffer is identical before and after ingestion, and ‖Δθ‖ = 0 exactly. No optimizer, no loss, no backward pass ran.

✗ "Nothing was learned, an activation just changed."
Also wrong. A linear-attention state update is fast-weight programming (Schlag et al. 2021), and one linear self-attention layer implements one step of gradient descent on a least-squares objective (von Oswald et al. 2023). Something with the algebraic form of learning happened.

✓ The defensible statement. The trained parameters are bit-identical before and after the demonstrations. What changes is a fixed-size state whose update rule is baked into the architecture. Whether you call that "learning" depends on whether you count the implicit inner model. What is not in dispute is that no gradient step was taken.
